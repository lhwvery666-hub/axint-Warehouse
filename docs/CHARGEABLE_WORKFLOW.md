# 收费维修确认流程

## 📋 用户需求

> "我现在流程分为两种不需要收费和需要收费所以当我需要收费的时候我们的维修人员需要把这个报告完成以后保存然后现场人员那边可以看到维修报告然后自己分析这个报告的产品是否维修和回寄然后签字回传报告我们的维修人员在进行维修和后续操作"

---

## 🔄 两种工作流程

### 流程A：不收费的情况（现有流程）

```
维修人员填写报告
↓
维修人员保存报告
↓
状态：正常流转
↓
现场人员查看报告（可选）
↓
现场人员确认是否回寄（可选）
↓
维修人员直接进行维修
↓
完成维修
↓
发货
```

**特点**：
- ✅ 流程简单直接
- ✅ 签字照片建议上传但非必须
- ✅ 现场确认是辅助性的

---

### 流程B：收费的情况（新增流程）⭐

```
维修人员填写报告（包含维修费用）
↓
维修人员保存报告
↓
状态：pending_reporter_confirm（等待现场确认）
↓
现场人员查看报告（看到维修内容和费用）
↓
现场人员与客户沟通
  ├─ 客户是否同意维修？
  ├─ 客户是否同意费用？
  └─ 是否要回寄设备？
↓
现场人员打印报告
↓
客户在报告上签字
↓
现场人员拍照上传签字报告（必须）
↓
现场人员提交确认
↓
维修人员看到客户确认
↓
状态：可以开始维修
↓
维修人员进行实际维修
↓
完成维修
↓
后续操作（发货等）
```

**特点**：
- ⚠️ 必须等待现场人员确认
- ⚠️ 必须上传签字照片
- ⚠️ 客户明确同意后才能维修
- ✅ 避免维修后客户不认账的风险

---

## 🎯 核心区别

| 项目 | 不收费 | 收费 |
|-----|--------|------|
| 现场确认 | ✅ 可选 | ⚠️ 必须 |
| 签字照片 | ✅ 建议上传 | ⚠️ 必须上传 |
| 维修前提 | ✅ 无需等待 | ⚠️ 必须等待现场确认 |
| 工单状态 | - | `pending_reporter_confirm` |
| 客户签字 | ✅ 可选 | ⚠️ 必须 |

## 🔧 技术实现

### 1. 数据库字段

**使用的字段**：
- `IsChargeable` (BIT) - 是否收费
- `Status` (NVARCHAR) - 工单状态
- `SignedReportPhoto` (NVARCHAR) - 签字照片路径
- `RepairReportContent` (NVARCHAR) - 维修报告内容（包含费用）

### 2. API 修改

**文件**: `app/api/tickets/batch-repair-report/[batchId]/route.ts`

**修改**：
```typescript
// 查询时添加 IsChargeable 和 Status 字段
SELECT 
  ...
  ${DB_FIELDS.SIGNED_REPORT_PHOTO},
  ${DB_FIELDS.IS_CHARGEABLE},  // ✅ 新增
  ${DB_FIELDS.STATUS}          // ✅ 新增
FROM Repair_Tickets
WHERE ${DB_FIELDS.BATCH_ID} = @batchId

// 返回数据中添加
const batchInfo = {
  ...
  isChargeable: firstRecord[DB_FIELDS.IS_CHARGEABLE] || false,  // ✅ 新增
  status: firstRecord[DB_FIELDS.STATUS] || "Created",            // ✅ 新增
}
```

## 📱 使用场景示例

### 场景 1：免费维修（现有流程）

**背景**：设备在保修期内，免费维修

```
1. 维修人员填写报告：
   - 维修内容：更换电池
   - 维修费用：¥0.00
   - IsChargeable: false ✅

2. 维修人员保存报告
   - 状态：正常流转

3. 现场人员（可选操作）：
   - 查看报告
   - 确认回寄
   - 建议上传签字照片（非必须）

4. 维修人员：
   - 直接开始维修
   - 完成后发货
```

---

### 场景 2：收费维修（新流程）⚠️

**背景**：设备过保，需要收取维修费用 ¥1,500.00

```
1. 维修人员填写报告：
   - 维修内容：更换主板
   - 维修费用：¥1,500.00
   - IsChargeable: true ⚠️

2. 维修人员保存报告
   - 状态：pending_reporter_confirm
   - ⏳ 维修人员看到提示："请等待现场人员与客户确认"

3. 现场人员收到通知：
   - 查看维修报告
   - 看到 ⚠️ 橙色提示：本次维修需要收费 ¥1,500.00
   - 看到明确的操作指引

4. 现场人员与客户沟通：
   - 向客户说明维修内容和费用
   - 询问客户是否同意维修
   
   情况A：客户同意维修
   ├─ 打印维修报告
   ├─ 让客户在报告上签字
   ├─ 拍照上传签字报告（必须）
   └─ 设置"是否回寄"为 ✅
   
   情况B：客户拒绝维修
   ├─ 打印维修报告
   ├─ 让客户在报告上签字（说明不维修原因）
   ├─ 拍照上传签字报告（必须）
   └─ 设置"是否回寄"为 ✅（直接退回）

5. 现场人员提交确认：
   - 系统验证：
     ✅ 已选择"是否回寄"
     ✅ 已上传签字照片
   - 如果没有上传照片：
     ⛔ 提示："本次维修需要收费（¥1,500.00），必须上传客户签字的报告照片"
     ⛔ 阻止提交

6. 提交成功后：
   - 状态更新
   - 维修人员收到通知："现场已确认，可以开始维修"

7. 维修人员：
   - 查看客户签字照片
   - 确认客户同意后，开始维修
   - 完成维修
   - 后续操作
```
