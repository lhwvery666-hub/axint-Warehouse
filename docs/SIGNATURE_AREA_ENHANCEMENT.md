# 签字确认区域增强功能

## 📋 需求背景

> "你看这张图中间有一个客户签字盖章的签名处我们没有你给我添加一下"

用户提供的图片显示，维修报告中应该包含完整的签字确认区域，包括：
1. 返回方式
2. 制单人
3. 复核
4. 客户签字确认（盖章）
5. 外购产品

---

## ✅ 已实现功能

### 1. 新增签字确认区域

**位置**：维修报告底部，备注区域下方

**布局**：
```
┌─────────────────────────┬─────────────────────────┐
│ 返回方式：配套           │ 制单人：[用户名]        │
├─────────────────────────┼─────────────────────────┤
│ 复核：                  │ 客户签字确认（盖章）：   │
│ [留空供手写]            │ [签字照片或留空]        │
├─────────────────────────┴─────────────────────────┤
│ 外购产品：[留空供手写]                            │
├───────────────────────────────────────────────────┤
│ 维修负责人：[用户名]     │ 日期：[当前日期]        │
└───────────────────────────────────────────────────┘
```

### 2. 字段说明

| 字段 | 数据来源 | 说明 |
|-----|---------|------|
| **返回方式** | 目前固定为"配套" | ⚠️ 需要确认：是固定值还是需要可配置？ |
| **制单人** | `user?.realName \|\| user?.username` | 当前登录用户的真实姓名或用户名 |
| **复核** | 留空 | 供手写或盖章 |
| **客户签字确认** | `signedPhoto` | 如果有签字照片，显示缩略图；否则留空 |
| **外购产品** | 留空 | 供手写 |
| **维修负责人** | `user?.realName \|\| user?.username` | 维修人员姓名 |
| **日期** | `format(new Date(), 'yyyy-MM-dd')` | 当前日期 |

### 3. 客户签字确认显示逻辑

#### 有签字照片时：
```
┌─────────────────────────────────┐
│ 客户签字确认（盖章）：           │
│                                 │
│  [签字照片缩略图]               │
│                                 │
└─────────────────────────────────┘
```

**样式**：
- 照片最大高度：70px
- 自动缩放适应框
- 带边框和圆角
- 保持原始比例

#### 无签字照片时：
```
┌─────────────────────────────────┐
│ 客户签字确认（盖章）：           │
│                                 │
│  [虚线框 - 留空供签字]          │
│                                 │
└─────────────────────────────────┘
```

**样式**：
- 虚线边框
- 灰色背景
- 高度：60px

## ⚠️ 需要确认的问题

### 1. 返回方式的数据来源

**当前实现**：硬编码为"配套"

**问题**：
- 是所有工单都是"配套"？
- 还是有不同的返回方式（如：快递、自取、配送等）？

**建议方案**：
```typescript
// 如果需要可配置，添加到数据库：

// 1. 添加枚举（lib/enums.ts）
export enum ReturnMethod {
  PACKAGE = '配套',
  EXPRESS = '快递',
  PICKUP = '自取',
  DELIVERY = '配送',
}

// 2. 添加数据库字段
// scripts/add-return-method-column.ts
ALTER TABLE Repair_Tickets 
ADD ReturnMethod NVARCHAR(50) DEFAULT '配套'

// 3. 在报告中显示
<span className="signature-value">
  {reportData?.batchInfo?.returnMethod || ReturnMethod.PACKAGE}
</span>
```

### 2. 制单人的数据来源

**当前实现**：显示当前登录用户

**问题**：
- 制单人是创建工单的人，还是当前查看/打印的人？
- 如果是创建工单的人，需要在数据库中记录

**建议方案**：

#### 方案A：制单人 = 当前用户（已实现）
```typescript
// 优点：简单，无需数据库修改
// 缺点：不同人打印时显示不同

<span className="signature-value">
  {user?.realName || user?.username || '-'}
</span>
```

#### 方案B：制单人 = 创建工单的人
```typescript
// 需要数据库字段：CreatedBy, CreatedByName

// 1. 数据库查询时包含创建人信息
SELECT 
  CreatedBy,
  CreatedByName
FROM Repair_Tickets

// 2. 在报告中显示
<span className="signature-value">
  {reportData?.batchInfo?.createdByName || '-'}
</span>
```
